# v0.5.0 — Architecture refactor plan

This document is the migration plan for the v0.5.0 architectural
refactor. It is **deferred from v0.4.8.x** because the changes are
risky (touch every module's import path) and the current architecture
is functionally clean — the refactor is for publication-quality
posture, not bug-fixing.

The plan is committed here so the work is concrete and trackable;
v0.5.0 will be its own deliberate release where every step below is
executed and tested.

## Goals

1. **Formalize the pipeline as a DAG** with `AuditNode` /
   `AuditGraph` so dependencies are explicit and parallelizable.
2. **Strong typing** on audit results (`MetricResult`, `AuditResult`)
   so contracts between modules / aggregators / renderers are
   machine-checkable.
3. **Reorganize `core/` into themed sub-folders** for readability:
   `core/math/`, `core/vision/`, `core/ml/`, `core/reasoning/`,
   `core/infra/`.
4. **Maintain 100% backward compatibility** at the public-API level —
   `cineinfini audit ...`, `cfg/profiles/*.yaml`, all 21 modules,
   data.json schema.

## Non-goals (explicitly out of scope for v0.5.0)

- Distributed execution (Ray / Dask). Current pipeline is single-
  machine; that's fine.
- Pydantic schema validation of YAML. Manual validation suffices.
- Replacing the registry pattern with anything fancier.
- Performance optimization. Refactor first; optimize later.

## Step 1 — Add `types/` module (additive, zero risk)

Create `src/cineinfini/types/` with three dataclasses:

```python
# types/metrics.py
@dataclass
class MetricResult:
    name: str
    value: Optional[float]
    confidence: float = 1.0
    metadata: Dict[str, Any] = field(default_factory=dict)
    version: str = "1.0"

@dataclass
class ShotResult:
    shot_id: int
    metrics: Dict[str, MetricResult]
    verdict: str = "REVIEW"
    failed_gates: List[str] = field(default_factory=list)

@dataclass
class AuditResult:
    video_name: str
    version: str
    duration_s: float
    n_shots: int
    shots: Dict[int, ShotResult]
    composite_score: Optional[float] = None
    timing: Dict[str, float] = field(default_factory=dict)
    rendered: Dict[str, Optional[str]] = field(default_factory=dict)
```

These types **do not replace** the dict-based output yet — they
coexist. Existing code keeps working. Renderers and exporters can
opt into the typed view via `AuditResult.from_dict(audit_data)`.

**Test plan**: 5 new tests verifying round-trip dict ↔ AuditResult.
**Risk**: zero — additive only.

## Step 2 — Add `pipeline/graph.py` (additive)

Create the DAG abstraction:

```python
# pipeline/graph.py
@dataclass
class AuditNode:
    name: str
    inputs: List[str]
    outputs: List[str]
    compute: Callable
    version: str = "1.0"

class AuditGraph:
    def __init__(self):
        self._nodes: Dict[str, AuditNode] = {}
        self._deps: Dict[str, List[str]] = {}

    def add_node(self, node: AuditNode) -> None: ...
    def add_dependency(self, src: str, dst: str) -> None: ...
    def topological_order(self) -> List[str]: ...      # Kahn's algorithm
    def execute(self, ctx: VideoContext) -> AuditResult: ...
```

The default `AuditGraph` factory builds a graph from
`get_active_modules()` + their declared `requires=[...]`, producing a
graph isomorphic to the current sequential orchestrator. Activation
via `cfg.processing.dag_execution = true` (default `false` in v0.5.0
to keep stability).

**Test plan**: 8 new tests — topological ordering, cycle detection,
execution order matches the legacy orchestrator on test fixtures.
**Risk**: zero behavior change when `dag_execution = false`.

Backward compat: keep stub modules at the old paths that re-export
the symbols:

```python
# core/config.py (compatibility shim)
import warnings
warnings.warn(
    "cineinfini.core.config is deprecated; use cineinfini.core.infra.config",
    DeprecationWarning, stacklevel=2,
)
from cineinfini.core.infra.config import *  # noqa: F401,F403
```

**Migration script**:

```bash
#!/bin/bash
# scripts/migrate_v050.sh
mkdir -p src/cineinfini/core/{math,vision,ml,reasoning,infra}
git mv src/cineinfini/core/config.py src/cineinfini/core/infra/config.py
# ...etc per the table
# Then run sed to fix internal imports:
find src/cineinfini -name "*.py" -exec sed -i \
    's|cineinfini.core.config|cineinfini.core.infra.config|g' {} +
# Repeat per migration line
```

**Test plan**: full pytest suite (232 tests) MUST stay green after
each `git mv` + sed pass. Run after each line of the migration table,
not at the end.

**Risk**: high. This is why it's a separate release. Mitigation:

1. Migrate one file at a time, run the full suite each time.
2. Keep deprecation shims for 2 minor versions (v0.5.x → v0.7.0).
3. The PR description includes a `find . -name "*.py" -exec grep -l 'core.config'`
   command users can run on their own code to find calls that need updating.

## Why this is in v0.5.0 and not v0.4.8.x

The v0.4.8.x line is feature-complete and recruiter-tested. Doing
this refactor in a 0.4.8.x release would risk breaking the working
audit pipeline for purely architectural reasons. The right
engineering move is:

1. Ship v0.4.8.x as the stable, feature-complete line
2. Cut a `v0.5-dev` branch
3. Do the refactor incrementally, with the full test suite as the
   gate at every step
4. Release v0.5.0 only when every box above is checked

This document exists so the work is committed in writing — not
forgotten or hand-waved.
